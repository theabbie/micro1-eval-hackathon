# FHIR R4 search results for task T09 (hypertension registry)

## How quantity prefixes behave on this server

- A search value like `90` has an implicit range of **[89.5, 90.5)**, based on its precision.
- `ge90` matches any target ≥ 90.5. It also matches any target that overlaps [89.5, 90.5).
- In practice, **≥ 89.5 matches `ge90`**, and **≥ 139.5 matches `ge140`**.
- So the decimal device values in bp-09 (139.6 and 89.6) match `ge140` and `ge90`.
- `gt90` matches only targets above 90.5.

## q1: separate parameters, no composite

`component-code=…|8462-4&component-value-quantity=ge90`

- The two parameters are evaluated independently. Each one can be satisfied by a *different* component of the same Observation.
- All nine BP panels have a component with code 8462-4. This includes bp-06, whose diastolic component has a code but only a dataAbsentReason.
- Every panel's systolic component is ≥ 90, so the value test always passes on systolic.
- **Result: bp-01 through bp-09.**
  - hr-01 and sbp-01 have no components, so they don't match.
  - bp-08 still appears because there is no status filter.

- Diastolic ≥ 90: bp-02, bp-04, bp-07, bp-08, bp-09.

- Removing bp-08 (status entered-in-error) leaves **bp-01, bp-02, bp-04, bp-06, bp-07, bp-09.**

## q4: systolic ≥ 140 AND diastolic ≥ 90

- This is the intersection of the two sets above: **bp-04, bp-07, bp-09.**
- bp-06 drops out because its diastolic component has no value.

## q5: systolic eq 140

- `140` means the range [139.5, 140.5).
- bp-07 (140) and bp-09 (139.6) both fall inside it.
- **Result: bp-07, bp-09.**

## q6: code-value-quantity with systolic code

- This parameter only looks at Observation.code and Observation.valueQuantity at the top level.
- The panels have top-level code 85354-9 and no valueQuantity, so they don't match.
- **Result: sbp-01 only** (152).

## q7: value-quantity gt90

- No code is specified, so any Observation with a top-level valueQuantity above 90.5 matches.
- hr-01 (98 beats/min) and sbp-01 (152 mmHg) both match.
- Including the heart rate is a registry pitfall: the query is not restricted to blood pressure.
- **Result: hr-01, sbp-01.**

## Takeaways for the registry

- **q1 is broken:** it flags every panel. Use the composite form (q2/q3) so the code and value are tested on the same component.
- **Decimals near the threshold match:** values like 139.6 and 89.6 match `ge140` and `ge90` because of implicit precision ranges. If that is not intended, write the threshold with more precision (e.g. `ge140.0`) so the matching range is narrower.
- **Standalone systolic Observations are missed:** composite component searches don't find sbp-01. Add a `code-value-quantity` query (q6) to catch it.
