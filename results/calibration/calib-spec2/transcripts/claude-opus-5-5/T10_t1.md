# T10 Patient Search Results

**String search defaults (R4):** A plain string search matches when the target starts with the search value. It ignores case and accents. It applies to any part of the name element: for `name`, that is family, given, prefix, suffix and text. This server also splits family names into parts on spaces and hyphens. `:contains` matches anywhere in the string. `:exact` requires a full match and is sensitive to case and accents.

**Token search defaults:** `system|code` matches one specific system and value. A bare `code` matches that value in any system. `:of-type` takes `typeSystem|typeCode|value` and matches the identifier's type together with its value.

- **q1 `name=munoz`**
  - p-01 matches: "Muñoz" folds to "munoz".
  - p-07 matches through its old name "Munoz". Every HumanName is searched, including old names.
- **q2 `family=quinones`**
  - p-02 matches. "Carreño Quiñones" splits into the part "Quiñones", which starts with "quinones" once accents are ignored.
- **q3 `given=eve`** (starts with "eve")
  - p-03 matches (Eve), as do p-04 (Evelyn), p-09 (EVE) and p-10 (Eve).
  - p-05 "Séverine" does not match because it starts with "sev".
  - p-08 does not match because "Eve" is its family name, not its given name.
- **q4 `given:contains=eve`**
  - Matches everything q3 matched.
  - Also matches p-05: "Séverine" folds to "severine", which contains "eve".
- **q5 `given:exact=Eve`**
  - p-03 and p-10 match.
  - p-09 "EVE" does not match because `:exact` is case-sensitive.
- **q6 `name=jon`**
  - p-03 matches: the family part "Jones" comes from splitting "Smith-Jones".
  - p-06 matches through "Jones".
  - p-08 matches through its given name "Jon".
  - p-05 "Johansson" does not match.
- **q7 `family:exact=Smith`**
  - p-10 matches.
  - p-03 matches because the server searches family names by their parts for the `family` parameter, and the part "Smith" is an exact match.
  - p-09 "SMITH" and p-04 "Smithers" do not match.
- **q8 hospital MRN `|000123`**
  - p-01 matches.
  - p-02 has the value "123". Token values are compared exactly, so it does not match.
  - p-03 has the same value but a different system.
- **q9 `identifier=000123`** (any system)
  - p-01 and p-03 match.
  - p-06 also matches through its driver's licence identifier, which has the value 000123.
- **q10 `:of-type` MR|000123**
  - p-01 and p-03 match.
  - p-06's 000123 identifier has the type DL, not MR, so it does not match.
- **q11 `name=dr&gender=male`**
  - p-06 matches: its prefix "Dr." starts with "dr" and its gender is male.
