**Key points**

- `component-code` and `component-value-quantity` in q1 are separate parameters, so they match independently. The code match can come from the DBP component and the value match from the SBP component.
- Composite parameters (q2, q3, q5) must match on the same component. Separate composite parameters (q4) match independently.
- `ge90` uses the implicit range [89.5, 90.5), so 89.6 matches. `ge140` uses [139.5, 140.5), so 139.6 matches. `eq140` also matches 139.6.
- `code-value-quantity` and `value-quantity` look only at top-level `code`/`valueQuantity`, never at components.
- Nothing filters on status by default, so `entered-in-error` bp-08 is returned unless `status=final` is added.

**Per query**

- **q1:** Every panel has a DBP component with code 8462-4, and every panel has an SBP component ≥ 90. The independent match makes all nine panels match, including bp-03 (120/80) and bp-05 (135/88), which are not above goal. bp-06 matches on the code alone. hr-01 and sbp-01 have no components, so they do not match.
- **q2:** Same-component DBP ≥ 90 (with overlap): bp-02 (95), bp-04 (92), bp-07 (90), bp-08 (91, not status-filtered), bp-09 (89.6 overlaps 90). bp-06 has no DBP value.
- **q3:** The comma makes the two composites an OR. Matching components are SBP ≥ 140 (bp-01, bp-04, bp-06, bp-07, bp-09) or DBP ≥ 90 (bp-02, bp-04, bp-07, bp-08, bp-09). `status=final` removes bp-08.
- **q4:** Two separate composites (AND). SBP ≥ 140 set ∩ DBP ≥ 90 set = bp-04, bp-07, bp-09.
- **q5:** Same-component eq 140 with overlap: SBP 140 (bp-07) and 139.6 (bp-09). The `eq` prefix doesn't check the sign of the difference, so it matches both sides of 140.
- **q6:** Only sbp-01 has top-level code 8480-6, with value 152. Panel components do not count.
- **q7:** `value-quantity` checks top-level values only. hr-01 (98) and sbp-01 (152) are > 90. No unit filter is applied, so the unit does not matter.

**Caveat on bp-09 (139.6/89.6):** These matches depend on the overlap rule. Under strict comparison (v ≥ 90 or v ≥ 140), bp-09 drops out of q2, q3, q4, and q5. Clinically, 139.6 and 89.6 are below the thresholds, so the registry should decide on decimal handling explicitly rather than rely on this behaviour.

**Registry recommendations**

- Use the same-component composite (q3) for the "above goal" criterion, and add `status=final`.
- Decide how decimal readings are compared to thresholds.
- Exclude bp-06, where the DBP has only a dataAbsentReason.
- Handle the standalone systolic (sbp-01) with a separate query, because it is not a panel component.
