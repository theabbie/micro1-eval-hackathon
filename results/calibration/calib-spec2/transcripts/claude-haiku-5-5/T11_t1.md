## Per-query analysis

**Key points used throughout**
- The server does not filter on Observation status, so `o-6` (`entered-in-error`) still matches searches on its code and value.
- Value searches with no unit match on the number alone, so `o-4` (250 mg/dL) counts for `gt9`.
- Each `_has` parameter is evaluated independently, so two `_has` parameters can be satisfied by different Observations. A composite parameter requires both components to match the same Observation.
- `_include` and `_revinclude` are applied once to the match set and are not recursive.
- `o-8` references `Patient/pt-9`, which is not on the server.

**q1: `_has` code AND `_has` value-quantity (independent)**
- Patients with a 4548-4 Observation: pt-1 (o-1), pt-2 (o-3), pt-3 (o-5), pt-5 (o-6). pt-9 is absent.
- Patients with any Observation value > 9: pt-1 (o-1, o-2), pt-2 (o-4, 250), pt-3 (o-5), pt-5 (o-6, o-7). pt-4 is excluded (max 95).
- Intersection: pt-1, pt-2, pt-3, pt-5. pt-2 matches through different Observations (o-3 for code, o-4 for value).

**q2: composite `code-value-quantity` (same Observation)**
- Observations with 4548-4 and value > 9: o-1 (9.5), o-5 (9.2), o-6 (10.1). o-8 (11.0) is on pt-9, which is not a Patient on the server, so it does not affect this result. o-3 (7.0) fails.
- Patients: pt-1, pt-3, pt-5.

**q3: q2 AND `_has` status=final**
- The status `_has` is a separate, independent condition. pt-1 (o-1), pt-3 (o-5), and pt-5 (o-7 is final) each have a final Observation.
- Result: pt-1, pt-3, pt-5.

**q4: composite Observation search with `patient.gender=female`**
- Composite matches: o-1, o-5, o-6, o-8. o-8's subject does not exist, so the chain fails.
- Female subjects: o-1 (pt-1), o-5 (pt-3). o-6 (pt-5) is male.
- Result: o-1, o-5.

**q5: composite Observation search with `_include=Observation:patient`**
- Matches: o-1, o-5, o-6, o-8. The composite search does not check the subject, so o-8 is included in the match set.
- Includes: pt-1, pt-3, pt-5. pt-9 is not on the server, so nothing is included for o-8.

**q6: `patient=pt-2` with `_revinclude=Provenance:target`**
- Matches: o-3, o-4.
- Provenance targeting these: prov-2 (targets o-3 and o-4). prov-1 targets o-1 and is not included.

**q7: `_has` code AND gender=female, with two `_revinclude`s**
- Patients with a 4548-4 Observation: pt-1, pt-2, pt-3, pt-5. Female: pt-1, pt-3.
- `Provenance:target` reverse-includes provenance whose target is a matched Patient: prov-3 (targets pt-1). prov-1 targets o-1, which is not in the match set, so it is not included.
- `Observation:patient` reverse-includes Observations of the matched patients: pt-1 gives o-1 and o-2; pt-3 gives o-5.
- The includes are not followed further, so prov-1 is not added via o-1.
