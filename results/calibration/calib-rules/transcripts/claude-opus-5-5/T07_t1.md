# T07 Results: Body-Weight Quantity Queries

## Which resources are in scope for each unit filter

- **`|http://unitsofmeasure.org|kg`** (system and code must both match): w-01, w-02, w-03, w-04, w-06, w-07, w-09.
  - w-09 qualifies because its `unit` is "kilograms" but its `code` is "kg".
- **`||kg`** (`Quantity.code` OR `Quantity.unit` equals "kg"): the seven above plus w-08.
  - w-08 has `unit: "kg"` and no system.
- **Never in scope:**
  - w-05 uses code `[lb_av]` and unit `lb`. The server does no unit conversion, so it is excluded even though 220.5 lb ≈ 100 kg.
  - w-10 has only a `valueString`, so it has no value for the parameter and never matches, even with `ne`.

## Query-by-query analysis

**q1: `100|UCUM|kg`**
- `eq` uses the implicit range of "100", which is [99.5, 100.5).
- In range: w-01 (100), w-02 (100.4), w-04 (99.5), w-06 (100.04), w-07 (99.94), w-09 (100.0).
- Excluded: w-03 (100.5), because the upper bound is exclusive.

**q2: `100.0|UCUM|kg`**
- The implicit range of "100.0" is [99.95, 100.05).
- In range: w-01, w-06 (100.04), w-09.
- Excluded: w-07 (99.94) is below the range.

**q3: `100||kg`**
- Same range as q1, [99.5, 100.5), but the code-or-unit match adds w-08.
- Result: w-01, w-02, w-04, w-06, w-07, w-08, w-09.

**q4: `gt100|UCUM|kg`**
- `gt` compares exactly, so the value must be greater than 100.
- Result: w-02 (100.4), w-03 (100.5), w-06 (100.04).

**q5: `ne100|UCUM|kg`**
- `ne` means the value is outside [99.5, 100.5).
- Among UCUM-kg resources, only w-03 (100.5) qualifies.
- w-05 and w-10 are not in scope, as explained above.

**q6: `lt100.0||kg`**
- `lt` compares exactly, so the value must be less than 100.
- Result: w-04 (99.5), w-07 (99.94).

## Implications for the dosing check

- An `eq` search at "100" also returns 99.5 kg and 100.4 kg. If the dosing rule depends on a hard threshold, use `ge`/`lt` comparisons instead of `eq`.
- Weights recorded in pounds (w-05) are silently missed. Convert or normalize units before you rely on these queries for dosing.
