## Reply

## How the date of service is interpreted

The query value `2024-11-03` has no offset, so it is read in America/New_York. That local day runs from 00:00 EDT to 00:00 EST the next day, which is 25 hours because of the fall-back:

**S = [2024-11-03T04:00:00Z, 2024-11-04T05:00:00Z)**

## Each resource converted to UTC

Values with seconds are 1-second intervals. Values without an offset are read as New York local time.

| id | T (UTC) | Position relative to S |
|---|---|---|
| k-01 | Nov 3 04:30:00Z | inside |
| k-02 | Nov 3 03:30:00Z | before S |
| k-03 | Nov 4 04:30:00Z | inside (the 25th hour) |
| k-04 | Nov 4 05:00:00Z | at or after the end of S |
| k-05 | 01:30 EDT = Nov 3 05:30Z | inside |
| k-06 | 01:30 EST = Nov 3 06:30Z | inside |
| k-07 | 12:00+05:30 = Nov 3 06:30Z | inside |
| k-08 | local day = exactly S | inside |
| k-09 | 23:45 local (EST) = Nov 4 04:45Z | inside |
| k-10 | local month = [Nov 1 04:00Z, Dec 1 05:00Z) | spans both sides of S |
| k-11 | [Nov 3 02:00Z, Nov 3 11:00:01Z) | starts before S, ends inside |
| k-12 | 01:00 EDT = Nov 3 05:00Z | inside |
| k-13 | 01:00 EST = Nov 3 06:00Z | inside |

## Query results

**q1 (eq):** T must lie entirely inside S.
Matches: k-01, k-03, k-05, k-06, k-07, k-08, k-09, k-12, k-13.

**q2 (two conditions, both required):**
- `ge` on the minute [05:00Z, 05:01Z): some instant of T must be at or after 05:00Z.
- `lt` on the minute [06:00Z, 06:01Z): some instant of T must be before 06:00Z.

Matches:
- k-05 (05:30Z)
- k-08 (whole day)
- k-10 (whole month)
- k-11 (02:00Z to 11:00Z)
- k-12 (05:00:00Z, which counts for `ge` because it is at the start)

Excluded:
- k-13: it is exactly 06:00Z, so it is not before 06:00Z.
- k-01 and k-02: entirely before 05:00Z.
- k-06, k-07, k-03 and k-09: nothing before 06:00Z.

**q3 (sa):** every instant of T must be at or after Nov 4 05:00Z. Only k-04 qualifies.

**q4 (eb):** every instant of T must be before Nov 3 04:00Z. Only k-02 qualifies. k-11 extends into S, so it does not.

**q5 (ne):** this is "not eq" among resources that have a date. It returns k-02, k-04, k-10 and k-11.
