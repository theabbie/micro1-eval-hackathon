Quantity matching rules applied (all resource data here is synthetic):

- **eq** uses the implicit range of the search number. The prefix table requires the search range to fully contain the target value's own implicit range, so precision on the target matters.
- **ne** is the complement: the search range does not fully contain the target's range. The system and code must still match, so w-05, w-08 and w-10 stay out.
- **gt, lt** compare exactly, with no implicit range.
- With `system|code`, both must match. With `||kg`, there is no system constraint, and `kg` matches either `code` or `unit`.

**q1: `100|UCUM|kg`.** The search range is [99.5, 100.5).
- w-01 (100): range [99.5, 100.5), contained, so it matches.
- w-02 (100.4): [100.35, 100.45), contained, so it matches.
- w-03 (100.5): [100.45, 100.55), not contained.
- w-04 (99.5): [99.45, 99.55), not contained.
- w-06 (100.04) and w-07 (99.94) are contained, so they match.
- w-09 (100.0, code kg, UCUM) matches.
- w-05 (lb) is excluded, w-08 has no system, and w-10 has no quantity.

**q2: `100.0|UCUM|kg`.** The search range is [99.95, 100.05).
- w-01 (100) has range [99.5, 100.5), which is not contained.
- w-06 (100.04): [100.035, 100.045), contained, so it matches.
- w-07 (99.94): [99.935, 99.945), not contained.
- w-09 (100.0): [99.95, 100.05), contained, so it matches.

**q3: `100||kg`.** The search range is [99.5, 100.5), and the system is not constrained.
- It matches the same resources as q1, plus w-08, which has unit kg and value 100.
- w-05 is excluded because its unit is lb and its code is [lb_av].

**q4: `gt100|UCUM|kg`.** The comparison is exact: the value must be greater than 100.
- w-02 (100.4), w-03 (100.5) and w-06 (100.04) match.
- w-01 and w-09 equal 100 exactly, so they do not match.

**q5: `ne100|UCUM|kg`.** The target range must not be fully contained in [99.5, 100.5).
- w-03 and w-04 match.

**q6: `lt100.0||kg`.** The comparison is exact: the value must be less than 100.
- w-04 (99.5) and w-07 (99.94) match.
