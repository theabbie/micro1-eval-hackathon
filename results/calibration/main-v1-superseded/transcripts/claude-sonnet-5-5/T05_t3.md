**q1: `clinical-status=active&onset-date=lt2020-01-01`**
- Token matching is case-sensitive and has no system given, so any system with code `active` matches. That gives c-01, c-03, c-04, c-05, c-07 and c-08. c-10 has code `Active`, which does not match.
- For `lt`, the range below ends at 2020-01-01 00:00 PST, and the target must intersect it.
- c-01 matches.
- c-05 matches because its period starts in 2019.
- c-07 matches because 23:30 PST on 12-31 is before the cutoff.
- c-08 does not match, because 01:00 PST on 1 January is after the cutoff.
- c-03 and c-04 have no indexed onset.
- Result: c-01, c-05, c-07.

**q2: `clinical-status=active,recurrence,relapse&onset-date=ge2020-01-01`**
- The status OR list matches c-01, c-02, c-03, c-04, c-05, c-07 and c-08.
- For `ge`, the target must overlap the search day or lie after it.
- c-05 matches because its period runs to the end of February 2020.
- c-08 matches.
- c-07 does not match, because it falls on 12-31 PST.
- c-01 and c-02 are earlier.
- Result: c-05, c-08.

**q3: `onset-date:missing=true`**
- Result: c-03, c-04, c-11.

**q4: `clinical-status:not=active`**
- `:not` also returns resources with no clinicalStatus.
- Excluded, because they have code `active`: c-01, c-03, c-04, c-05, c-07, c-08.
- Returned: c-02 (recurrence), c-06 (resolved), c-09 (no clinicalStatus), c-10 (`Active`, case differs), c-11 (inactive).

**q5: `onset-date=2019`**
- `eq` uses the implicit range 2019-01-01 00:00 to 2019-12-31 23:59:59 PST, and the target range must fall within it.
- c-02 matches.
- c-07 matches, because 23:30 PST on 2019-12-31 is inside the range.
- c-05 does not match, because its period extends into 2020.
- Result: c-02, c-07.
