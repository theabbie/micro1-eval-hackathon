## Reply

**Day window.** America/New_York on 2024-11-03 runs from 00:00 EDT to 00:00 EST the next day, which is [2024-11-03T04:00Z, 2024-11-04T05:00Z). This window is 25 hours long.

**Resource instants (UTC) and local day:**

| id | UTC value / range | Falls on local 11-03? |
|---|---|---|
| k-01 | 11-03 04:30Z | yes |
| k-02 | 11-03 03:30Z | no (23:30 EDT on 11-02) |
| k-03 | 11-04 04:30Z | yes (23:30 EST) |
| k-04 | 11-04 05:00Z | no (exactly the end, exclusive) |
| k-05 | 11-03 05:30Z | yes |
| k-06 | 11-03 06:30Z | yes |
| k-07 | 11-03 06:30Z | yes |
| k-08 | date 2024-11-03 = [04:00Z, 11-04 05:00Z) | equals the window |
| k-09 | 23:45 local (EST) = 11-04 04:45Z | yes |
| k-10 | 2024-11 = the whole month | contains the window, not contained in it |
| k-11 | period 11-03 02:00Z to 11:00Z | starts before the window |
| k-12 | 11-03 05:00Z | yes |
| k-13 | 11-03 06:00Z | yes |

**q1** (`eq`) requires the target range to be fully inside the search range. That gives k-01, 03, 05, 06, 07, 08, 09, 12, 13. k-10 and k-11 are not fully contained, and k-02 and k-04 are outside the window.

**q2** is an AND of two conditions:
- `ge 05:00Z` matches targets that overlap or lie above the range.
- `lt 06:00Z` matches only targets entirely below 06:00Z.
- k-05 (05:30Z) and k-12 (05:00Z) satisfy both.
- k-13 (06:00Z) fails `lt`.
- k-08 and k-11 pass `ge` through overlap but fail `lt`.
- k-01 and k-02 fail `ge`.

**q3** (`sa`) requires the target to start at or after the end of the range, 11-04 05:00Z. Only k-04 qualifies.

**q4** (`eb`) requires the target to end at or before the start of the range, 11-03 04:00Z. Only k-02 qualifies. k-10 and k-11 overlap the range.

**q5** (`ne`) returns everything not matched by q1: k-02, k-04, k-10, k-11.

**q6** (`eq`) searches 01:30-05:00, which is 06:30Z with minute precision, so the range is [06:30:00, 06:31:00). Only k-06 and k-07 fall inside it. k-05 is at 05:30Z, and k-13 is at 06:00Z.
