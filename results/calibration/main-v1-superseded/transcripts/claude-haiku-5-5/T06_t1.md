Local time is America/New_York (EDT, UTC-4 in July). Each Encounter is indexed by its `period` interval, and a date search matches when that interval satisfies the prefix rules. Converted to local time:

| id | Local interval | Notes |
|---|---|---|
| e-01 | Jun 28 22:00 → Jul 3 11:00 | spans the June/July boundary |
| e-02 | Jul 30 20:00 → (open) | ongoing, no end |
| e-03 | Jul 15 09:00 → 09:30 | inside July |
| e-04 | Jul 31 23:10 → Aug 1 02:40 | spans the July/August boundary |
| e-05 | Jul 31 22:00 → 22:30 | 02:00Z–02:30Z converted; inside July |
| e-06 | Jul 1 00:00 → Jul 31 23:59:59.999 | month precision |
| e-07 | Jun 30 23:30 → Jul 1 08:00 | spans the June/July boundary |
| e-08 | no period | no date value |
| e-09 | Jun 30 23:30 → 23:50 | 03:30Z–03:50Z converted; entirely June |
| e-10 | (open) → Jul 10 23:59:59.999 | end-only; date-only end covers the whole day |

**q1: `date=2024-07`.** The search range is Jul 1 00:00 to Jul 31 23:59:59.999, and `eq` matches on overlap. Everything that touches July matches. e-08 has no value and e-09 is entirely in June, so both are excluded.

**q2: `date=ge2024-07-01&date=le2024-07-31`.** `ge2024-07-01` matches anything ending on or after Jul 1 00:00 (or open-ended). `le2024-07-31` matches anything starting on or before Jul 31 23:59:59.999 (or with no start). The AND gives the same set as q1.

**q3: `class=…|IMP&date=sa2024-06-30`.** `sa` requires the target to start after Jun 30 23:59:59.999. Among IMP encounters, e-01 starts in June and e-08 has no period, so only e-02 qualifies.

**q4: `date=gt2024-07-31`.** `gt` requires the target to extend past Jul 31 23:59:59.999. e-04 ends Aug 1 02:40, and e-02 is ongoing (open-ended, so it extends past that point). e-06 ends exactly at the boundary, which is not strictly greater, so it is excluded.

**q5: `date=lt2024-07-01&class=AMB,OBSENC`.** `lt` requires the target to start before Jul 1 00:00. Among AMB and OBSENC encounters: e-07 (OBSENC, starts Jun 30) and e-09 (AMB, starts Jun 30) match. e-10 has no start, so it extends below Jul 1 and matches. e-06 starts exactly at Jul 1 00:00, so it does not match.

**q6: `date:missing=true`.** Only e-08 has no `period`. e-10 has an `end`, so it is indexed and does not match.

**Assumptions:** an open `period.end` is treated as ongoing (extends past any 2024 search range), and a date-only `end` is taken as the end of that day. The results for q2, q4 and q5 depend on these readings. Ordering is lexicographic, so `e-10` sorts after `e-09`.
