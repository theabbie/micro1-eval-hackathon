## T04 query results

Here is how each query resolves, with all date ranges taken in America/Chicago local time.

**Approach**

- Values with an offset or `Z` are converted to Chicago time: CDT is UTC−5 in summer and CST is UTC−6 in winter.
- Values with no offset are treated as Chicago local time.
- Each value becomes an implicit range. Ranges are half-open, meaning the end point itself is excluded.
- Only date-typed values are indexed. imm-03 and imm-10 use `occurrenceString`, so the `date` parameter has no value for them.

**Indexed date ranges**

| imm-03 | occurrenceString | completed | not indexed |

**q1: `date=2019-05`**
- With no prefix (`eq`), the target range must lie fully inside [2019-05-01 00:00, 2019-06-01 00:00) CDT.
- imm-01, imm-04, imm-05, imm-07 and imm-09 match. imm-05 falls on the evening of May 31 local time.
- imm-02 does not match because a full year is not contained in May.
- imm-06 and imm-08 fall outside May.

**q2: `date=ne2019-05`**
- This returns indexed targets that are *not* fully contained in May 2019: imm-02, imm-06 and imm-08.
- The `ne` prefix is not the `:not` modifier, so resources with no value (imm-03, imm-10) are not returned.

**q3: `date=2019`**
- The search range is [2019-01-01 00:00 CST, 2020-01-01 00:00 CST).
- imm-01, imm-02, imm-04, imm-05, imm-07, imm-08 and imm-09 match.
- imm-08 matches because it is 2019-12-31 23:30 local time.
- imm-06 does not match because it is 2018-12-31 23:00 local time.

**q4: `date=le2019-05-31&status=completed`**
- `le` matches when the target overlaps the "range below" (everything before 2019-05-31 00:00) or overlaps the search day itself.
- In practice, this means the target must start before 2019-06-01 00:00 CDT.
- That covers imm-01, imm-02, imm-04, imm-05, imm-06, imm-07 and imm-09.
- imm-08 is excluded because it falls after that point.
- `status=completed` then removes imm-07, leaving imm-01, imm-02, imm-04, imm-05, imm-06 and imm-09.

**q5: `date:missing=true`**
- imm-03 and imm-10 match, because `occurrenceString` is not indexed by a date parameter.

**q6: `vaccine-code=cvx|03&date=gt2019-05-14`**
- The vaccine code matches imm-01, imm-02 and imm-03.
- For `gt`, the "range above" starts at 2019-05-15 00:00. The target range must overlap it.
- imm-01 does not match. Its range ends exactly at 2019-05-15 00:00, and that end point is excluded, so the ranges do not overlap.
- imm-02 matches because the 2019 range overlaps.
- imm-03 has no indexed date.
- The result is imm-02.
