## Reply

Default string matching is case-insensitive, accent-insensitive and prefix-based. Under this server's rules, family names are also matched by their parts, split on spaces and hyphens. `:exact` is case- and accent-sensitive against the whole value. `:contains` matches a substring anywhere in the whole value, ignoring case and accents.

**q1 `name=munoz`**
- p-01 matches: "Muñoz" normalizes to "munoz".
- p-07 matches through its old (maiden) name "Munoz". The `name` parameter covers every HumanName, whatever its `use` or period.
- **Result:** p-01, p-07.

**q2 `family=quinones`**
- p-02's family "Carreño Quiñones" splits into "Carreño" and "Quiñones". "Quiñones" matches after removing the accent.
- **Result:** p-02.

**q3 `given=eve`** (starts-with)
- Eve (p-03), Evelyn (p-04), EVE (p-09) and Eve (p-10) match.
- Séverine (p-05) does not start with "eve".
- p-08 has "Eve" only as a family name, and `given` does not search family.
- **Result:** p-03, p-04, p-09, p-10.

**q4 `given:contains=eve`**
- Adds Séverine (p-05): "severine" contains "eve". This mirrors the R4 spec's own example, which lists Eve, Evelyn and Severine.
- **Result:** p-03, p-04, p-05, p-09, p-10.

**q5 `given:exact=Eve`**
- Only an exact, case-sensitive "Eve" matches: p-03 and p-10.
- "EVE" (p-09) and "Evelyn" (p-04) do not.
- **Result:** p-03, p-10.

**q6 `name=jon`**
- p-08 matches on given name "Jon".
- p-06 matches on family "Jones".
- p-03 matches because "Smith-Jones" splits into "Smith" and "Jones", and "Jones" starts with "jon".
- "Johansson" (p-05) does not match, since "joh" is not "jon".
- **Result:** p-03, p-06, p-08.

**q7 `family:exact=Smith`**
- Only p-10 matches.
- "SMITH" (p-09) differs in case.
- "Smith-Jones" (p-03) does not match because `:exact` compares the whole value with no splitting.
- **Result:** p-10.

**q8 `identifier=<hospital mrn>|000123`**
- p-01 matches.
- p-02's value is "123", which is a different token from "000123".
- p-03 has the right value but a different system.
- **Result:** p-01.

**q9 `identifier=000123`** (any system)
- p-01 (hospital MRN), p-03 (clinic MRN) and p-06 (driver's licence) all have the value "000123".
- **Result:** p-01, p-03, p-06.

**q10 `identifier:of-type=…v2-0203|MR|000123`**
- p-01 and p-03 have type MR with value "000123".
- p-06's matching value is typed DL, so it is excluded.
- **Result:** p-01, p-03.

**q11 `name=dr&gender=male`**
- p-06 matches: its prefix "Dr." starts with "dr", and it is male.
- The other males, p-01 and p-08, have no name part starting with "dr".
- **Result:** p-06.
