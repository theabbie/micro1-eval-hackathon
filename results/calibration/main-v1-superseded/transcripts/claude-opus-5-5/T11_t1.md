# T11 FHIR R4 Search Results: Reverse Chaining, Chaining and Includes

## Key principles

- **Separate `_has` parameters are evaluated independently.** Each one may be satisfied by a different Observation. A composite parameter, by contrast, must be satisfied within a single Observation.
- **Chained parameters and `_has` only reach resources that exist on this server.** Observation `o-8` references `Patient/pt-9`, which is not on the server.
- **`_include` and `_revinclude` without `:iterate`** apply only to the resources that matched the search. They do not apply to resources that were themselves included.
- **`value-quantity=gt9` compares exactly** against 9, as the server's rules state.

## Per-query analysis

**q1** (two independent `_has` parameters)
- Observations with code 4548-4 have subjects pt-1 (o-1), pt-2 (o-3), pt-3 (o-5) and pt-5 (o-6). The subject of o-8 is pt-9, which is not on the server.
- Observations with value-quantity > 9 have subjects pt-1 (o-1, o-2), pt-2 (o-4 = 250), pt-3 (o-5), pt-5 (o-6, o-7) and pt-4 (o-9 = 95).
- The intersection is pt-1, pt-2, pt-3 and pt-5.
- pt-2 qualifies only because two different Observations satisfy the two conditions: o-3 has the code and o-4 has the value. This is the classic false positive of this query pattern.

**q2** (composite parameter: code and value in the same Observation)
- Matching Observations are o-1 (9.5), o-5 (9.2), o-6 (10.1) and o-8 (11.0). o-3 (7.0) fails.
- The patients on the server are pt-1, pt-3 and pt-5.

**q3** (q2 plus an independent `_has` on status=final)
- pt-1 has a final Observation (o-1). pt-3 has one (o-5).
- pt-5's HbA1c Observation (o-6) is entered-in-error. However, pt-5 also has a separate final Observation (o-7), so pt-5 still matches.
- The result is pt-1, pt-3 and pt-5.

**q4** (composite plus chained `patient.gender=female`)
- The composite matches o-1, o-5, o-6 and o-8.
- o-1 (pt-1, female) and o-5 (pt-3, female) qualify.
- o-6 is excluded because pt-5 is male.
- o-8 is excluded because its patient, pt-9, cannot be resolved on the server.

**q5** (composite plus `_include=Observation:patient`)
- Matches are o-1, o-5, o-6 and o-8.
- The includes are pt-1, pt-3 and pt-5. pt-9 does not exist, so nothing is included for o-8.

**q6** (`patient=pt-2` plus `_revinclude=Provenance:target`)
- Matches are o-3 and o-4.
- prov-2 targets both of them, so it is included.

**q7** (patients with an HbA1c Observation who are female, plus two revincludes)
- Patients with an HbA1c Observation on the server are pt-1, pt-2, pt-3 and pt-5. Of these, pt-1 and pt-3 are female.
- `_revinclude=Provenance:target` adds prov-3, which targets pt-1.
- `_revinclude=Observation:patient` adds o-1, o-2 and o-5.
- prov-1 is **not** added. It targets o-1, but o-1 was itself included rather than matched, and there is no `:iterate`.
