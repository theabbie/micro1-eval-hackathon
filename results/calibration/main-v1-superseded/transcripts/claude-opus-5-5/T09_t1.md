# FHIR R4 Search Results for T09: Blood-Pressure Component vs Composite Queries

**Key takeaways for the registry**
- **Use composite parameters for BP.** Separate `component-code` and `component-value-quantity` can match values from different components. In q1 this returns 4 false positives (bp-01, bp-05, bp-06, bp-09).
- **Panel and standalone searches don't overlap.** Composite component queries never find the standalone systolic Observation (sbp-01). `code-value-quantity` never finds the panels. Covering both needs two queries.
- **Filter on status.** Only q3 filters on `status=final`. Every other query can return the entered-in-error bp-08.
- **`eq` and `ge` treat decimals differently.** A plain number uses an implicit range, so `140` matches 139.6. `ge140` and `ge90` compare exactly, so bp-09 (139.6/89.6) is never flagged as above goal.

**q1: `component-code=…|8462-4 & component-value-quantity=ge90`**
- These are two independent parameters, so they are not tied to the same component.
- Every panel bp-01 to bp-09 has a component coded 8462-4, including bp-06, whose diastolic has only a `dataAbsentReason`.
- Each panel needs any component value ≥ 90:
  - bp-01 matches (systolic 150).
  - bp-02 matches (95).
  - bp-03 does not match (120/80).
  - bp-04 matches (145).
  - bp-05 matches (135).
  - bp-06 matches (160).
  - bp-07 matches (140).
  - bp-08 matches (128).
  - bp-09 matches (139.6).
- There is no status filter.
- **Result:** bp-01, bp-02, bp-04, bp-05, bp-06, bp-07, bp-08, bp-09.

**q2: composite `8462-4$ge90`**
- The diastolic component itself must be ≥ 90:
  - bp-02 matches (95).
  - bp-04 matches (92).
  - bp-07 matches (90).
  - bp-08 matches (91).
- bp-09 does not match: `ge` compares exactly and 89.6 < 90.
- bp-06 does not match because its diastolic has no value.
- **Result:** bp-02, bp-04, bp-07, bp-08.

**q3: (systolic ≥ 140 OR diastolic ≥ 90) AND status=final**
- Systolic ≥ 140: bp-01, bp-04, bp-06, bp-07. bp-09 is excluded (139.6).
- Diastolic ≥ 90: bp-02, bp-04, bp-07, bp-08.
- `status=final` removes bp-08.
- sbp-01 has no components, so the component composite cannot match it.
- **Result:** bp-01, bp-02, bp-04, bp-06, bp-07.

**q4: systolic ≥ 140 AND diastolic ≥ 90**
- Each composite is evaluated against its own component.
- **Result:** bp-04, bp-07.

**q5: composite `8480-6$140`**
- With no prefix, the search uses `eq`, whose implicit range is [139.5, 140.5).
- bp-07 matches (140).
- bp-09 matches (139.6).
- **Result:** bp-07, bp-09.

**q6: `code-value-quantity=…|8480-6$ge140`**
- This searches the top-level `Observation.code` and `Observation.valueQuantity`.
- The panels are coded 85354-9, so they do not match.
- **Result:** sbp-01 only (152).

**q7: `value-quantity=gt90`**
- This searches the top-level value only. Units are not checked.
- hr-01 matches (98 /min).
- sbp-01 matches (152 mmHg).
- The panels have no top-level value.
- **Result:** hr-01, sbp-01. Adding a `|system|code` unit or a `code` filter would exclude the heart rate.
