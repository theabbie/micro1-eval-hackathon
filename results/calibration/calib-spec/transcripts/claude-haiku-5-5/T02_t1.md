## Reply

**Day boundaries (America/New_York):** 2024-11-03 begins at 00:00 EDT = 2024-11-03T04:00Z and ends at 2024-11-04T00:00 EST = 2024-11-04T05:00Z. Local time is EST (UTC-5) after 01:00 EDT on Nov 3, when the clocks fall back.

**Per-resource instants used below (UTC):**

| id | Instant or range (UTC) |
|---|---|
| k-01 | Nov 3 04:30 |
| k-02 | Nov 3 03:30 |
| k-03 | Nov 4 04:30 |
| k-04 | Nov 4 05:00 |
| k-05 | Nov 3 05:30 |
| k-06 | Nov 3 06:30 |
| k-07 | Nov 3 06:30 |
| k-08 | Nov 3 local day, [04:00, 05:00 next day) |
| k-09 | Nov 4 04:45 (23:45 EST on Nov 3) |
| k-10 | Nov month, [Nov 1 04:00, Dec 1 05:00) |
| k-11 | Period [Nov 3 02:00, Nov 3 11:00] |
| k-12 | Nov 3 05:00 |
| k-13 | Nov 3 06:00 |

**q1 (`date=2024-11-03`, eq):** The search range must fully contain the data range. This matches k-01, k-03, k-05, k-06, k-07, k-08, k-09, k-12 and k-13. It excludes k-02 (before the day), k-04 (exactly at the exclusive end), k-10 (the month is wider than the day) and k-11 (the period starts before the day).

**q2 (`ge` 05:00Z AND `lt` 06:00Z):** `ge` (start 05:00Z, with overlap) requires the data range to end at or after 05:00Z. `lt` (06:00Z) requires the data range to start before 06:00Z. This matches k-05, k-08, k-10, k-11 and k-12. It excludes k-06, k-07 and k-13 (they start at or after 06:00Z), and k-01, k-02, k-03, k-04 and k-09 (they end before 05:00Z or start after 06:00Z on Nov 3).

**q3 (`sa2024-11-03`):** The data must start after the search range ends (after 04:59:59.999Z on Nov 4). Only k-04 (05:00:00Z) qualifies.

**q4 (`eb2024-11-03`):** The data must end before the search range starts (before 04:00Z on Nov 3). Only k-02 (03:30Z) qualifies. k-11 overlaps the day, so it does not match.

**q5 (`ne2024-11-03`):** This is the complement of q1 across the resources, since every resource has a date value. It returns k-02, k-04, k-10 and k-11.
