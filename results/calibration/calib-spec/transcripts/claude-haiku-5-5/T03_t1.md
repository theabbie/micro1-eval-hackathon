## Reply

The day 2024-06-15 is in EDT (UTC-4), so the local search range is 2024-06-15T00:00 to 23:59:59.999 America/New_York, which is 2024-06-15T04:00Z to 2024-06-16T04:00Z exclusive.

**Converted instants and periods (local time)**
- m-06: 2024-06-16T02:00Z = 2024-06-15 22:00 EDT. Inside the day.
- m-07: 2024-06-15T02:00Z = 2024-06-14 22:00 EDT. Before the day.
- m-10: 2024-06-15T08:00-04:00 = 2024-06-15 08:00 EDT. Inside the day.
- m-12: 2024-06-15T21:00-07:00 = 2024-06-16 00:00 EDT. Just after the day.
- Day- and month-precision bounds expand to the full period. m-09 starts at 2024-06-01 and ends at the end of 2024-06-20.
- Status is not a filter in q1–q4 and q6, so m-08, m-10 and m-12 are included or excluded only on their dates.

**q1** `ge2024-06-15&le2024-06-15`: the two bounds together match any target that overlaps the day.
- Matches: m-01 (open start, from 2024-01-10), m-02 (on the day), m-04 (ends on the day), m-05 (open start, ends 2024-06-30), m-06 (22:00 local), m-09 (June 1–20), m-10 (08:00 local).
- Excludes: m-03 (ends 2024-06-14), m-07 (22:00 on the 14th), m-08 (starts 2024-06-16), m-12 (starts 2024-06-16 00:00 local), m-11 (no value).

**q2** `effective=2024-06-15`: equality is overlap with the day, so the result is the same set as q1.

**q3** `eb2024-06-15`: the target must end before the start of the day, 2024-06-15 00:00 local.
- Matches: m-03 (ends 2024-06-14) and m-07 (22:00 local on the 14th).
- m-11 is excluded because it has no value and `:not` is not used.

**q4** `sa2024-06-15`: the target must start after the end of the day, 2024-06-15 23:59:59.999 local.
- Matches: m-08 (starts 2024-06-16) and m-12 (starts 2024-06-16 00:00 EDT).
- m-05 is excluded because its start is unknown, so it cannot be shown to start after the day.

**q5** `q1` plus `status=active`: of the q1 set, only m-01, m-05 and m-06 are active. m-02 and m-04 are completed, m-09 is stopped and m-10 is entered-in-error.

**q6** `effective:missing=true`: only m-11 has no effective[x] value.
