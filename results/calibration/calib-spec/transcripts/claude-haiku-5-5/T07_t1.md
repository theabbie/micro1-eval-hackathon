## Matching rules applied

- **Precision:** The implicit range of a search or target value is ±half a unit in its last significant digit. `100` gives [99.5, 100.5), and `100.0` gives [99.95, 100.05). `100.04` gives [100.035, 100.045), and `99.94` gives [99.935, 99.945).
- **eq** (default): the search range must fully contain the target range.
- **ne:** the search range must not fully contain the target range.
- **gt:** the range above the search range (from its upper bound) must overlap the target range. I applied the same start/end logic the server uses for dates, since the spec defines "range above/below" the same way for quantities.
- **lt:** the range below the search range (up to its lower bound) must overlap the target range.
- **System and code:** if a system is given, it must match exactly. If the code is given, it must match exactly. No unit conversion is applied, so `[lb_av]` never matches `kg`.
- **Missing parts:** w-08 has a unit but no `system` or `code`, so it fails any query that specifies `kg`. w-10 has no `valueQuantity`, so it never matches.
