## Rules applied (FHIR R4 quantity and number search)

- **Implicit precision range for `eq` and `ne`:** the search value's significant figures define a range.
  - `100` means [99.5, 100.5), with the upper bound excluded.
  - `100.0` means [99.95, 100.05).
  - `ne` matches values outside that range.
- **`gt` and `lt`:** these compare against the exact value. R4 says "lt100 means less than exactly 100". The server's end-of-range rule applies only to date prefixes, not to quantities.
- **`number|system|code`:** the resource's `system` and `code` must both match.
  - w-05 (`[lb_av]`) is excluded because the server does no unit conversion.
  - w-08 has no `system` or `code`, so it never matches a system-qualified query.
- **`number||code`:** this matches the resource's `code` **or** its `unit`.
  - w-08 matches through `unit: "kg"`.
  - w-09 matches through `code: kg`, even though its unit text is "kilograms".
- **w-10:** it has `valueString` and no `valueQuantity`, so it is never indexed and never returned. `ne` is not `:not`, so the `:not` behaviour of returning resources with no value does not apply.
