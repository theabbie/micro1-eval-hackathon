## Reply

**q1: `name=munoz`**
- Default string matching is a starts-with match that ignores case and accents.
- `name` covers every HumanName on the Patient.
- p-01 matches through its official family name "Muñoz", which normalises to "munoz".
- p-07 matches through its old name "Munoz". Old names are still indexed.
- **Result: p-01, p-07**

**q2: `family=quinones`**
- p-02's family name "Carreño Quiñones" splits on the space into "Carreño" and "Quiñones".
- "Quiñones" normalises to "quinones" and matches.
- **Result: p-02**

**q3: `given=eve`**
- Starts-with, ignoring case, on given names:
  - p-03 (Eve) matches.
  - p-04 (Evelyn) matches.
  - p-09 (EVE) matches.
  - p-10 (Eve) matches.
- p-08 has "Eve" only as a family name, and `given` does not search family names.
- "Séverine" does not start with "eve".
- **Result: p-03, p-04, p-09, p-10**

**q4: `given:contains=eve`**
- `:contains` looks for the value anywhere in the whole given name, still ignoring case and accents.
- This adds p-05: "Séverine" normalises to "severine", which contains "eve".
- **Result: p-03, p-04, p-05, p-09, p-10**

**q5: `given:exact=Eve`**
- `:exact` requires the whole value to match, including case and accents.
- p-09's "EVE" fails because of case. p-04's "Evelyn" fails because it is not the whole value.
- **Result: p-03, p-10**

**q6: `name=jon`**
- p-08 matches on given name "Jon".
- p-06 matches on family name "Jones", which starts with "jon".
- p-03 matches because "Smith-Jones" splits on the hyphen into "Smith" and "Jones".
- "Johansson" does not start with "jon".
- **Result: p-03, p-06, p-08**

**q7: `family:exact=Smith`**
- "SMITH" fails because of case. "Smith-Jones" and "Smithers" fail because they are not the whole value. `:exact` never uses the split parts.
- **Result: p-10**

**q8: `identifier=system|value`**
- Both system and value must match. Token values are compared exactly, so "123" is not "000123".
- p-03 has value 000123 but a different system.
- **Result: p-01**

**q9: `identifier=000123`** (any system)
- p-01 matches on its hospital MRN.
- p-03 matches on its clinic MRN.
- p-06 matches on its driver's licence number.
- **Result: p-01, p-03, p-06**

**q10: `identifier:of-type=…|MR|000123`**
- The identifier's type must be MR and its value must be 000123.
- p-06's 000123 is typed DL, so it does not match.
- p-10 has no type, and its value differs anyway.
- **Result: p-01, p-03**

**q11: `name=dr&gender=male`**
- `name` also searches the prefix field, and "Dr." starts with "dr".
- p-06 is also male, so both conditions are met.
- **Result: p-06**
