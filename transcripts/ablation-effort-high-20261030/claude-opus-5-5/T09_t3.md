There are also two standalone Observations. hr-01 (heart rate, code 8867-4) has a top-level value of 98. sbp-01 (code 8480-6) has a top-level value of 152.

**q1: two separate, uncorrelated component parameters.** `component-code=8462-4` matches every resource with a diastolic component code. That is bp-01 through bp-09, including bp-06, whose component has a code but no value. `component-value-quantity=ge90` matches if *any* component value is 90 or more. Systolic values therefore count here. Only bp-03 fails, because both of its values (120 and 80) are below 90. bp-01 matches because of its systolic 150, even though its diastolic is 80. This is the classic false positive from searching uncorrelated components.
→ bp-01, 02, 04, 05, 06, 07, 08, 09

**q2: composite search, where code and value must be in the same component.** The query asks for a diastolic value of 90 or more. Matches are bp-02 (95), bp-04 (92), bp-07 (90) and bp-08 (91). bp-09 (89.6) does not match, because `ge` compares exactly. bp-06 has no diastolic value, so it does not match.
→ bp-02, 04, 07, 08

**q3: comma means OR, combined with status=final.**
- Systolic of 140 or more: bp-01, 04, 06, 07. bp-09 at 139.6 does not qualify.
- Diastolic of 90 or more: bp-02, 04, 07, 08.
- The union of these is bp-01, 02, 04, 06, 07, 08.
- Requiring `status=final` removes bp-08.

→ bp-01, 02, 04, 06, 07

**q4: repeated parameter means AND.** The resource must have systolic of 140 or more *and* diastolic of 90 or more. Each composite is evaluated within a single component, but the two can be satisfied by different components. Only bp-04 (145/92) and bp-07 (140/90) meet both conditions.
→ bp-04, 07

**q5: implicit eq with search value 140.** The implicit range of "140" is [139.5, 140.5). Stored values are treated as exact points. bp-07 (140) and bp-09 (139.6) fall inside the range.
→ bp-07, 09

**q6: code-value-quantity uses top-level Observation.code and valueQuantity.** The BP panels have code 85354-9 and no top-level value, so they cannot match. Only sbp-01 matches (code 8480-6, value 152).
→ sbp-01

**q7: value-quantity searches top-level Observation.valueQuantity only.** Component values are not indexed by this parameter. There is no unit conversion and no unit filter in the query. Matches are hr-01 (98 /min) and sbp-01 (152).
→ hr-01, sbp-01

**Registry implications:**
- q1 over-flags patients because it does not correlate code with value.
- q3 is the correct "above goal" query. It correctly excludes bp-09 (139.6/89.6) and bp-08 (entered-in-error).
- q7 mixes in a heart-rate value because the query has no code or unit filter.
