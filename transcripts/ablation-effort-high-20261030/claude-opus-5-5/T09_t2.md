# T09 Results: Component vs Composite Blood-Pressure Search

## Key behaviours

- **Separate parameters do not have to match the same component.** `component-code` and `component-value-quantity` are evaluated independently. Each can be satisfied by a different component of the same resource. Only the composite `component-code-value-quantity` requires the code and the value to come from the **same** component.
- **Top-level and component paths are separate.** `code-value-quantity` and `value-quantity` look only at `Observation.code` and `Observation.valueQuantity`. They never look at components.
- **Quantity comparisons:** `ge`, `gt`, `le` and `lt` compare exactly. Plain `eq` uses the search value's implicit range, so `140` means [139.5, 140.5).
- **No unit filter** is applied unless the query includes one.

## Per-query analysis

**q1**: `component-code=…|8462-4` AND `component-value-quantity=ge90`
- All nine BP panels (bp-01 to bp-09) have a component coded 8462-4. This includes bp-06, whose diastolic component has a code but no value.
- In every panel, at least one component value is ≥ 90. The systolic values alone qualify: 150, 130, 120, 145, 135, 160, 140, 128 and 139.6 are all ≥ 90.
- The two conditions are not tied to the same component, so all nine panels match.
- hr-01 and sbp-01 have no components, so they do not match.
- No status filter applies, so bp-08 (entered-in-error) is included.
- **Result: bp-01 to bp-09.**

**q2**: composite, diastolic ≥ 90 in the same component
- Matches: bp-02 (95), bp-04 (92), bp-07 (90), bp-08 (91).
- bp-09 does not match: 89.6 < 90 under exact comparison.
- bp-06 does not match: its diastolic component has no value.

**q3**: (systolic ≥ 140 OR diastolic ≥ 90) AND `status=final`
- Systolic ≥ 140: bp-01, bp-04, bp-06, bp-07. bp-09 is excluded because 139.6 < 140.
- Diastolic ≥ 90: bp-02, bp-04, bp-07, bp-08.
- Union: bp-01, 02, 04, 06, 07, 08.
- Removing the non-final bp-08 leaves **bp-01, 02, 04, 06, 07**.

**q4**: systolic ≥ 140 AND diastolic ≥ 90 (the two composite values are ANDed)
- **Result: bp-04, bp-07.**

**q5**: systolic = 140, using the implicit range [139.5, 140.5)
- bp-07 (140) matches.
- bp-09 (139.6) also matches, because it falls inside the range.
- sbp-01 has no components, so it does not match.

**q6**: `code-value-quantity` with top-level code 8480-6 and value ≥ 140
- Only sbp-01 (152) matches.
- The panels have top-level code 85354-9, so they do not match.

**q7**: `value-quantity=gt90` (top-level value only, no unit or code restriction)
- hr-01 (98 /min) and sbp-01 (152 mmHg) match.
- The panels have no top-level `valueQuantity`, so they do not match.

## Registry implications

- **q1 is unsafe as a registry query.** It flags every panel, including normotensive bp-03 and the entered-in-error bp-08. Use the composite form, as in q3.
- **q3 still misses the standalone systolic Observation sbp-01.** To catch it, add a separate `code-value-quantity=http://loinc.org|8480-6$ge140&status=final` query. Ideally, add a `mm[Hg]` unit qualifier to the quantity value as well.
- **Decimal values can fall just below the cut-off.** bp-09 (139.6/89.6) is not flagged by `ge140` or `ge90`. This is correct per the spec, but it may matter clinically depending on your rounding policy.
