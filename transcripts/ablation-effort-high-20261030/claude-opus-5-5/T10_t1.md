## Reply

**Applicable rules**
- **Default string search** is case-insensitive and accent-insensitive. It matches when the value equals or starts with the search term. Here it also matches family-name parts, split on spaces and hyphens.
- **`:contains`** matches the term anywhere in the whole element value, still ignoring case and accents.
- **`:exact`** must equal the whole element value, including case and accents.
- **Token search on `identifier`** is an exact match on the value. With `system|value`, both must match. With `:of-type`, the type, system and value must all be on the **same** identifier.

**q1 `name=munoz`**
- p-01 "Muñoz" matches, because accents are ignored.
- p-07 matches through its old name "Munoz". `name` searches every HumanName, whatever its `use` or period.
- Result: p-01, p-07.

**q2 `family=quinones`**
- p-02's family "Carreño Quiñones" is split on the space into "Carreño" and "Quiñones". The second part matches "quinones" with accents ignored.
- Result: p-02.

**q3 `given=eve`**
- "Eve" (p-03, p-10), "Evelyn" (p-04) and "EVE" (p-09) all start with "eve".
- "Séverine" (p-05) does not start with "eve".
- p-08 has "Eve" only as a family name, so `given` does not reach it.
- Result: p-03, p-04, p-09, p-10.

**q4 `given:contains=eve`**
- This returns the q3 matches plus p-05, because "Séverine" contains "eve" once accents are ignored.
- Result: p-03, p-04, p-05, p-09, p-10.

**q5 `given:exact=Eve`**
- Only p-03 and p-10 have exactly "Eve".
- "EVE" (p-09) fails because the case differs.
- Result: p-03, p-10.

**q6 `name=jon`**
- p-08 matches on given name "Jon".
- p-06 matches because "Jones" starts with "jon".
- p-03 matches because "Smith-Jones" is split on the hyphen, and the part "Jones" starts with "jon".
- "Johansson" (p-05) does not start with "jon".
- Result: p-03, p-06, p-08.

**q7 `family:exact=Smith`**
- Only p-10 matches.
- "SMITH" (p-09) fails on case.
- "Smith-Jones" (p-03) fails because `:exact` compares the whole element value.
- Result: p-10.

**q8 `identifier=<hospital mrn>|000123`**
- Only p-01 matches.
- p-02 has value "123", and token matching is not numeric, so it fails.
- p-03 and p-06 have "000123" under other systems.
- Result: p-01.

**q9 `identifier=000123`**
- With no system given, any system matches.
- Result: p-01, p-03, p-06 (p-06 through its driver's-licence identifier).

**q10 `identifier:of-type=…v2-0203|MR|000123`**
- p-01 and p-03 match.
- p-06 fails because its "000123" identifier has type DL, not MR.
- Result: p-01, p-03.

**q11 `name=dr&gender=male`**
- `name` includes the prefix. p-06's prefix "Dr." starts with "dr", and p-06 is male.
- No other patient has a name element starting with "dr".
- Result: p-06.
