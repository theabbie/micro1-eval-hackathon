**Key semantics applied**

- **Local time:** `America/Los_Angeles` is UTC-8 in January. So `2020-01-01T07:30:00Z` is `2019-12-31T23:30` local, and `2020-01-01T09:00:00Z` is `2020-01-01T01:00` local.
- **Indexing:** Only date-typed values are indexed by `onset-date`. `onsetAge` (c-03) and `onsetString` (c-04) are not indexed.
- **Case sensitivity:** `Active` (c-10) does not equal `active`.
- **Token queries:** `clinical-status` has no system in the query, so it matches on code only.
- **Date ranges:**
  - `lt2020-01-01` uses the range below the start of 2020-01-01 local.
  - `ge2020-01-01` uses the range above the end of the day, plus any target overlapping that day.
  - `2019` covers 2019-01-01 to 2020-01-01 local.
  - `eq` requires the search range to fully contain the target range. I applied this to Periods too, so c-05 is not contained in 2019.

**Active set:** c-01, c-03, c-04, c-05, c-07, c-08. Not active: c-02 (recurrence), c-06 (resolved), c-09 (no clinicalStatus), c-10 (`Active` is a case mismatch), c-11 (inactive).

**q1** (active AND onset lt 2020-01-01)
- c-01: 2018-03-02 matches.
- c-03, c-04: not indexed, so no match.
- c-05: Period 2019-10 to 2020-02 starts before 2020, so it intersects the range below. Match.
- c-07: 2019-12-31T23:30 local. Match.
- c-08: 2020-01-01T01:00 local. No match.

**q2** (clinical-status in {active, recurrence, relapse} AND onset ge 2020-01-01)
- c-01, c-02: 2018 and 2019-07-01. No.
- c-03, c-04: not indexed. No.
- c-05: Period overlaps 2020-01-01. Match.
- c-07: 2019-12-31 local, entirely before the day. No.
- c-08: 2020-01-01 local, inside the day. Match.

**q3** (onset-date:missing=true)
Resources with no indexed date value: c-03 (age), c-04 (string), c-11 (no onset). Every other resource has onsetDateTime or onsetPeriod, including c-06 (`2015`, a year-precision dateTime) and c-09.

**q4** (clinical-status:not=active)
Every Condition except the active set. This includes c-09, which has no clinicalStatus, and c-10, because of the case mismatch.

**q5** (onset-date=2019)
- c-02: 2019-07-01 is fully inside 2019. Match.
- c-07: 2019-12-31T23:30 local is inside 2019. Match.
- c-05: Period extends into 2020, so it is not contained. No match.
- c-06: `2015`, no. c-08: 2020, no. c-01, c-09, c-10: wrong years.
- c-03, c-04, c-11: not indexed.

Note that c-09 (entered-in-error) is not excluded by any query, because none filters on verification status.
