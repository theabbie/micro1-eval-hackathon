## Reply

**Approach:** Component-level criteria (`component-code`, `component-value-quantity`, and `component-code-value-quantity`) are evaluated per component. Separate parameters can match different components, while a composite matches a single component. Comma-separated values within one parameter are OR'd, and separate parameters are AND'd. Stored values are exact points, and only the search value has an implicit range (used by `eq`/`ne`). Only top-level `Observation.code`/`valueQuantity` feed `code-value-quantity` and `value-quantity`. Queries without `status` do not filter out `entered-in-error`.

**q1:** `component-code=8462-4` and `component-value-quantity=ge90` are independent. Every BP panel has a diastolic component code, including bp-06, whose diastolic has only a dataAbsentReason. Every panel also has some component ≥ 90, usually the systolic. The 90 threshold is met by a systolic value in every case, so the diastolic check is not actually enforced. Heart-rate and standalone systolic Observations have no components, so they are excluded. Result: bp-01 through bp-09.

**q2:** The composite requires the diastolic component itself to be ≥ 90. Matches: bp-02 (95), bp-04 (92), bp-07 (90, inclusive), bp-08 (91, entered-in-error but no status filter). Excluded: bp-01 (80), bp-03 (80), bp-05 (88), bp-06 (no value), bp-09 (89.6).

**q3:** Two composite conditions are OR'd: systolic ≥ 140 (same component) OR diastolic ≥ 90 (same component). Systolic ≥ 140 matches bp-01, bp-04, bp-06, bp-07. Diastolic ≥ 90 matches bp-02, bp-04, bp-07, bp-08. The union is bp-01, bp-02, bp-04, bp-06, bp-07, bp-08. `status=final` removes bp-08. bp-09 is excluded because 139.6 < 140 (exact comparison).

**q4:** Two composite parameters are AND'd, so the resource must satisfy both. Systolic ≥ 140 gives bp-01, bp-04, bp-06, bp-07. Diastolic ≥ 90 gives bp-02, bp-04, bp-07, bp-08. The intersection is bp-04 and bp-07.

**q5:** `$140` uses the default `eq`, whose implicit range for "140" is [139.5, 140.5). bp-07 (140) matches. bp-09 (139.6) falls inside that range and also matches, which is a registry concern: the search flags a systolic of 139.6 as 140. No other systolic value is in range.

**q6:** `code-value-quantity` uses `Observation.code` and top-level `valueQuantity`. Only sbp-01 has code 8480-6 at the top level with a value ≥ 140 (152). The BP panels have code 85354-9 and their systolic values sit in components, so they are not indexed.

**q7:** `value-quantity` uses top-level `valueQuantity` only. hr-01 (98) and sbp-01 (152) are both > 90. The panels have no top-level value.
