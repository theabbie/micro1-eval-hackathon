**Query ranges (search values use local time):**
- 2024-02: [02-01 00:00 EST, 03-01 00:00 EST)
- 2024-03: [03-01 00:00 EST, 04-01 00:00 EDT), so 05:00Z to 04:00Z the following day. The March range is 31 days but is not a fixed 744 hours because of DST.
- 2024-03-31 (day): [03-31 00:00 EDT, 04-01 00:00 EDT)
- 2024-03-01 (day): [03-01 00:00 EST, 03-02 00:00 EST)

**Semantics applied (R4 prefix table, plus the server's stated choices):**
- **eq** matches when the search range fully contains the data range. Partial overlaps do not match, so periods and year-level values such as g-09, g-15, and g-16 are excluded from month queries.
- **ne** is the complement of eq.
- **eb** matches when the data range ends at or before the search start, with no overlap.
- **sa** matches when the data range starts at or after the search end, with no overlap.
- **gt** matches when the data range overlaps the range above the search value, which starts at the search range end. The search value `2024-03-31T23:59-04:00` has an implicit minute range, so its range end is 04-01 04:00Z.
- **ge** and **le** match range overlaps as well as the boundary-based ranges. For `ge2024-03-01`, this means the data range ends after 03-01 05:00Z. For `le2024-03-31`, it means the data range starts before 04-01 04:00Z.
- Stored point values are treated as ranges at their written precision. For example, g-12 is [04:59:59, 05:00:00) and g-11 is [05:00:00, 05:00:01).

**Per-query notes:**
- **q1:** g-09 and g-15 are excluded because they are not fully contained in February. g-11 starts exactly at the exclusive end, so it is out.
