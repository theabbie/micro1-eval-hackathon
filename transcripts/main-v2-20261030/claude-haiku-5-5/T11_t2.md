**Data facts used**

- o-8 references Patient/pt-9, which is not on the server, so it can never produce a Patient match or an include.

**Assumption:** Each `_has` parameter is an independent condition, so separate parameters may be satisfied by different Observations. A composite (`code-value-quantity`) requires one Observation to satisfy both components.

**q1:** Code 4548-4 holds for pt-1, pt-2, pt-3, pt-5. Value > 9 holds for pt-1 (o-1), pt-3 (o-5), pt-5 (o-6). Intersection: pt-1, pt-3, pt-5. The result is the same even if both conditions must come from one Observation.

**q2:** The composite requires one Observation with code 4548-4 and value > 9: o-1, o-5, o-6. Patients: pt-1, pt-3, pt-5.

**q3:** The composite gives pt-1, pt-3, pt-5 as in q2. The separate `status=final` condition is met by any of the patient's Observations: o-1, o-5, and o-7 (final, for pt-5, even though o-6 is entered-in-error). All three remain. Result: pt-1, pt-3, pt-5.

**q4:** The composite matches o-1, o-5, o-6, o-8. The chain `patient.gender=female` keeps o-1 (pt-1 is female) and o-5 (pt-3 is female). It drops o-6 (pt-5 is male) and o-8 (pt-9 is not on the server). Result: o-1, o-5.

**q5:** Matches are o-1, o-5, o-6, o-8. `_include=Observation:patient` adds Patient/pt-1, pt-3, pt-5, all on the server. The reference to pt-9 yields nothing.

**q6:** Observations for pt-2 are o-3 and o-4. `_revinclude=Provenance:target` adds prov-2, which targets both. prov-1 and prov-3 target other resources and are not returned.

**q7:** Patients with a 4548-4 Observation are pt-1, pt-2, pt-3, pt-5. Female only: pt-1, pt-3. Revincludes are single-level (no `:iterate`):
- `Provenance:target` on pt-1 or pt-3 gives prov-3.
- `Observation:patient` on pt-1 or pt-3 gives o-1, o-2, o-5. The code filter does not apply to includes, so o-2 (LDL) is included.
- prov-1 (targets o-1) is not included, because it would be a second-level revinclude.
