## `clinical-status=active` matching

Token matching is case-sensitive, and a code with no system matches the code in any system. The following resources match:
- c-01, c-03, c-04, c-05, c-07, c-08

c-10 has the code `Active` (capital A), so it does **not** match `active`.

## Query results

**q1: `active` AND `lt2020-01-01`**

The "range below" ends at the start of the search value, which is `2020-01-01T08:00Z`. A resource matches if its range overlaps that range.
- c-01 matches.
- c-05 matches because its Period starts in 2019-10.
- c-07 matches because 07:30Z is before 08:00Z.
- c-08 does not match because it falls after midnight local time.
- c-03 and c-04 have no indexed date, so they cannot match.

**Result:** c-01, c-05, c-07

**q2: `active,recurrence,relapse` AND `ge2020-01-01`**

A resource matches if its range overlaps the local day 2020-01-01 or the range that starts at 2020-01-02T00:00 local and continues later.
- c-05 matches because its Period runs into Feb 2020.
- c-08 matches because it falls at 01:00 local on 2020-01-01.
- c-07 does not match because it falls on 2019-12-31 local.
- c-01 and c-02 do not match because their dates are too early.

**Result:** c-05, c-08

**q3: `onset-date:missing=true`**

Only date-typed values are indexed. That means Age, string, and absent onsets all count as missing.

**Result:** c-03, c-04, c-11

**q4: `clinical-status:not=active`**

This returns resources that lack the code `active`, including resources with no clinical-status value at all.
- c-02 (`recurrence`)
- c-06 (`resolved`)
- c-09 (no clinicalStatus)
- c-10 (`Active`, which differs in case)
- c-11 (`inactive`)

**Result:** c-02, c-06, c-09, c-10, c-11

**q5: `onset-date=2019`**

With `eq`, the target's range must lie fully inside the local year 2019.
- c-02 matches.
- c-07 matches because 2019-12-31T23:30 local is inside 2019.
- c-05 does not match because its Period extends into 2020.

**Result:** c-02, c-07

## Integration notes

The q4 result is a real risk for risk-adjustment logic:
- c-10 is clinically active but is missed by `clinical-status=active`.
- c-10 is also returned by `:not=active`.

The cause is its local code system and capitalisation. Consider mapping that code to the standard condition-clinical system, or querying with `system|code`. Also note that Age- and string-based onsets (c-03, c-04) can never satisfy date filters.
