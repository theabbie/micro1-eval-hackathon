## Reply

**Reasoning**

- **q1:** Two independent parameters are ANDed, so they can be satisfied by different components. Every BP panel has a diastolic component code (bp-06 still carries the code with a dataAbsentReason). Every panel also has some component value ≥ 90, because the systolic values are all ≥ 120. So bp-01 to bp-09 all match, including bp-08 because there is no status filter. hr-01 and sbp-01 have no components.
- **q2:** The composite requires the same component to be diastolic 8462-4 and ≥ 90. bp-02 (95), bp-04 (92), bp-07 (90) and bp-08 (91) match. bp-09 (89.6), bp-06 (no value), bp-05 (88), bp-01 (80) and bp-03 (80) do not.
- **q3:** The comma is OR within the composite, and `status=final` is ANDed, which removes bp-08.
  - Systolic ≥ 140: bp-01 (150), bp-04 (145), bp-06 (160), bp-07 (140).
  - Diastolic ≥ 90: bp-02 (95), bp-04, bp-07.
  - Result: bp-01, bp-02, bp-04, bp-06, bp-07.
- **q4:** Repeating the parameter is AND, and each instance can match a different component. The resource needs systolic ≥ 140 and diastolic ≥ 90. Only bp-04 (145/92) and bp-07 (140/90) qualify. bp-06 has no diastolic value.
- **q5:** `140` with no prefix is `eq`, with an implicit range of [139.5, 140.5). Systolic 140 (bp-07) and 139.6 (bp-09) both fall inside it.
- **q6:** `code-value-quantity` uses the top-level `Observation.code` and `valueQuantity`. Only sbp-01 (152) matches. The panels have code 85354-9, and their components are not indexed here.
- **q7:** `value-quantity` indexes only top-level `valueQuantity`, not components. hr-01 (98) and sbp-01 (152) are > 90.
