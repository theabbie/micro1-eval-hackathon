## Reply

Default string matching is case-insensitive, accent-insensitive and starts-with. `:contains` is case- and accent-insensitive substring matching. `:exact` is case- and accent-sensitive on the whole element value.

- **q1** `name=munoz`: p-01 matches because "Muñoz" equals "munoz" once accents are ignored. p-07 matches through its old-name entry "Munoz". Neither p-02 nor any other patient has a name starting with "munoz".
- **q2** `family=quinones`: p-02's family "Carreño Quiñones" is matched by its part "Quiñones".
- **q3** `given=eve`: starts-with on given names matches p-03 (Eve), p-04 (Evelyn), p-09 (EVE) and p-10 (Eve). p-08 has "Eve" only as a family name, so it is excluded.
- **q4** `given:contains=eve`: the same four match, plus two more because the substring "eve" appears once accents are ignored. These are p-05 ("Séverine", where "éve" matches) and p-06 ("Steve").
- **q5** `given:exact=Eve`: case-sensitive, so only p-03 and p-10 match; p-09's "EVE" does not.
- **q6** `name=jon`: p-08 matches on given "Jon" and p-06 on family "Jones". p-03 matches because "Smith-Jones" is split into parts and "Jones" starts with "jon". p-05 "Johansson" does not start with "jon".
- **q7** `family:exact=Smith`: whole-value, case-sensitive match gives only p-10. p-09 "SMITH" differs in case and p-03 "Smith-Jones" is not a whole-value match.
- **q8** `identifier=<hospital MRN system>|000123`: only p-01 has that system and value. p-03 uses the clinic system, and p-06's 000123 is a driver's licence number under a different system.
- **q9** `identifier=000123`: with no system constraint, p-01, p-03 and p-06 (its DL identifier) match. p-02's "123" is an exact-match miss.
- **q10** `identifier:of-type=...|MR|000123`: the type must be MR and the value 000123. That gives p-01 and p-03. p-06's 000123 has type DL, so it is excluded.
- **q11** `name=dr&gender=male`: p-06's prefix "Dr." matches "dr", and p-06 is male. No other patient has a name element starting with "dr".
