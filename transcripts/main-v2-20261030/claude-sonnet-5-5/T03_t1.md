## Reply

**Setup:** On 2024-06-15 New York is on EDT (UTC-4). The search value `2024-06-15` covers [06-15T00:00-04:00, 06-16T00:00-04:00), which is 04:00Z on 06-15 to 04:00Z on 06-16. I call this range S.

Each stored value is treated as an implicit range:

| Resource | Effective range |
|---|---|
| m-01 | [2024-01-10, open end) |
| m-02 | all of 06-15, ending at 06-16T00:00 EDT |
| m-03 | [05-01, 06-15T00:00 EDT) |
| m-04 | [05-01, 06-16T00:00 EDT) |
| m-05 | (open start, 07-01T00:00 EDT) |
| m-06 | instant 06-15T22:00 EDT (second precision) |
| m-07 | instant 06-14T22:00 EDT |
| m-08 | [06-16T00:00 EDT, open end) |
| m-09 | [06-01, 06-21) |
| m-10 | instant 06-15T08:00:00 EDT |
| m-11 | no value |
| m-12 | [06-16T00:00 EDT, open end), since 21:00-07:00 equals 04:00Z on 06-16 |

**q1:** `ge` combined with `le` on the same day, as an AND, returns every target that overlaps S.
- Matches: m-01, m-02, m-04, m-05, m-06, m-09, m-10.
- m-03 ends exactly at S's start, so it is out.
- m-08 and m-12 start exactly at S's end, so they are out.
- m-07 and m-11 are out.

**q2:** `eq` requires the target range to be fully contained in S.
- Matches: m-02, m-06, m-10.
- The open-ended and multi-day ranges are not contained.

**q3:** `eb` requires the target to lie entirely below S's start.
- Matches: m-03 (it ends exactly at S's start) and m-07.

**q4:** `sa` requires the target to start at or after S's end.
- Matches: m-08 and m-12.

**q5:** q1 restricted to `status=active` leaves m-01, m-05, m-06.
- m-02, m-04 and m-09 are not active.
- m-10 is entered-in-error.

**q6:** `:missing=true` matches only m-11.
- m-05 has an end-only period, which is indexed.

**q7:** The search value has minute precision, giving [08:00:00, 08:01:00) EDT. Only m-10 is contained in it.

**q8:** `ne` returns every target not fully contained in that one-minute range.
- Everything except m-10 matches.
- m-11 has no value, so `ne` does not return it.
