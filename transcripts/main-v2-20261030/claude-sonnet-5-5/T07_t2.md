**Rules applied**
- `eq` and `ne` use the implicit range of the search value. I take the range as half-open, [lower, upper), matching the rounding convention (99.5 rounds up to 100, 100.5 rounds up to 101).
  - `100` gives [99.5, 100.5).
  - `100.0` gives [99.95, 100.05).
- `gt` and `lt` compare exactly.
- With `system|code`, both must match. The `unit` display text is ignored, so w-09 "kilograms" still matches on code `kg`.
- With `|code` or `||code`, the code or the unit may match. The system is not required, so w-08 (unit `kg`, no system) matches.
- There is no unit conversion, so w-05 (`[lb_av]`) never matches a `kg` query.
- w-10 has no `valueQuantity`, so it never matches. `ne` does not return resources with no value.

**q1: `100|UCUM|kg`, range [99.5, 100.5)**
- w-01 (100), w-02 (100.4), w-04 (99.5, inclusive lower bound), w-06 (100.04), w-07 (99.94) and w-09 (code `kg`) match.
- w-03 (100.5) is excluded by the exclusive upper bound.
- w-08 has no system, so it fails the system check.
- w-05 is in lb.

**q2: `100.0|UCUM|kg`, range [99.95, 100.05)**
- w-01 (100), w-06 (100.04) and w-09 (100.0) match.
- w-07 (99.94) falls just below the range.

**q3: `100||kg`, range [99.5, 100.5), code or unit `kg`**
- This is the q1 set plus w-08, which matches on unit `kg`.

**q4: `gt100|UCUM|kg`, exact comparison**
- w-02 (100.4), w-03 (100.5) and w-06 (100.04) match.
- w-05 is in lb, so it does not match even though 220.5 > 100.

**q5: `ne100|UCUM|kg`, outside [99.5, 100.5)**
- Only w-03 (100.5) matches.
- w-04 (99.5) is inside the range.
- w-05 and w-08 fail the system/code requirement.

**q6: `lt100.0||kg`, exact comparison, code or unit `kg`**
- w-04 (99.5) and w-07 (99.94) match.
- w-08 (exactly 100) is not less than 100.
