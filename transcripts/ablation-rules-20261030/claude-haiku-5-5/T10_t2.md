**Per-query reasoning**

- **q1 `name=munoz`**: Default matching is accent-insensitive and prefix-based. p-01's family "Muñoz" matches. p-07 matches through its old name "Munoz". The server does not filter on the name's `period`, so the 2015 end date doesn't exclude it.
- **q2 `family=quinones`**: Family matching also checks split parts. p-02's family "Carreño Quiñones" splits into "Quiñones", which matches accent-insensitively.
- **q3 `given=eve`**: Prefix match on given names only. Matches "Eve" (p-03, p-10), "Evelyn" (p-04), and "EVE" (p-09, case-insensitive). "Séverine" and "Steve" are not prefixes, and p-08's family "Eve" is not a given name.
- **q4 `given:contains=eve`**: Substring match. Adds p-05 ("Séverine" contains "eve") and p-06 ("Steve" contains "eve").
- **q5 `given:exact=Eve`**: Whole-value, case-sensitive. Only p-03 and p-10 have exactly "Eve". p-09's "EVE" fails the case check.
- **q6 `name=jon`**: Matches p-08's given "Jon" and p-06's family "Jones" (prefix). "Johansson" does not start with "jon".
- **q7 `family:exact=Smith`**: Whole-value, case-sensitive. Only p-10 has family "Smith". "Smith-Jones", "Smithers", and "SMITH" fail.
- **q8 `identifier=<system>|000123`**: Requires the hospital system and value 000123. Only p-01. p-03 uses the clinic system, and p-06's 000123 is under the DL system.
- **q9 `identifier=000123`**: Any system. Matches p-01, p-03, and p-06 (its DL identifier).
- **q10 `identifier:of-type=…|MR|000123`**: The identifier must have type MR and value 000123. p-06's 000123 has type DL, so it fails. Matches p-01 and p-03.
- **q11 `name=dr&gender=male`**: p-06's prefix "Dr." matches "dr" (prefix parts are included in name searches). Gender must also be male, which p-06 is.
