**Time conversion.** The server zone is America/Los_Angeles, which is UTC-8 in January. The two UTC onsets therefore fall on different local days:
- c-07: 2020-01-01T07:30Z = 2019-12-30T23:30 local
- c-08: 2020-01-01T09:00Z = 2020-01-01T01:00 local

**Onset values indexed by `onset-date`.** Only dateTime and Period are indexed. c-03 (onsetAge), c-04 (onsetString) and c-11 (no onset) have no indexed value.

**Clinical status.** c-10 uses a local system and the code "Active". Token matching is case-sensitive, so it does not match `active`. c-09 has no clinicalStatus at all; its verificationStatus is entered-in-error, which does not affect this parameter.

**q1: `clinical-status=active` AND `onset-date=lt2020-01-01`**
- Active set: c-01, c-03, c-04, c-05, c-07, c-08.
- Onset before 2020-01-01 local start: c-01 (2018-03-02) matches. c-05 (period starting 2019-10-01) matches. c-07 (local 2019-12-30) matches.
- c-08 (local 2020-01-01 01:00) is not before the start, so it does not match. c-03 and c-04 have no value.
- Result: c-01, c-05, c-07.

**q2: `clinical-status=active,recurrence,relapse` AND `onset-date=ge2020-01-01`**
- Status set: c-01, c-02, c-03, c-04, c-05, c-07, c-08.
- ge matches any target at or after the search start, or overlapping the search range.
- c-05 overlaps 2020-01-01 (its period runs to 2020-03-01), so it matches.
- c-08 is at local 2020-01-01 01:00, so it matches.
- c-07 ends at local 2019-12-30 23:31, before the search start, so it does not match.
- c-01 and c-02 are 2018 and 2019. c-03 and c-04 have no value.
- Result: c-05, c-08.

**q3: `onset-date:missing=true`**
- Resources with no indexed onset-date value: c-03 (Age), c-04 (string), c-11 (none).
- Result: c-03, c-04, c-11.

**q4: `clinical-status:not=active`**
- Excluded are the resources whose clinicalStatus has the token `active` in any system: c-01, c-03, c-04, c-05, c-07, c-08.
- Included are everything else, including resources with no clinicalStatus: c-02 (recurrence), c-06 (resolved), c-09 (no clinicalStatus), c-10 ("Active" does not match `active`), c-11 (inactive).
- Result: c-02, c-06, c-09, c-10, c-11.

**q5: `onset-date=2019`**
- Search interval: [2019-01-01, 2020-01-01) local. For eq, every instant of the resource must fall inside it.
- c-02 (2019-07-01) matches.
- c-07 (local 2019-12-30 23:30) matches.
- c-05 extends into 2020, so it does not match. c-08 (local 2020-01-01 01:00) is outside. c-06 is 2015, c-01 is 2018, c-09 is 2017, c-10 is 2016.
- Result: c-02, c-07.
